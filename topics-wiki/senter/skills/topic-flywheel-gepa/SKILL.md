# topic-flywheel-gepa
# Topic flywheel (context → skills → bots → loops)

1. Read inbox.md + continuity.md; only new evidence counts.
2. Skill: propose only from REPEATED evidence (>=2 verbatim Chris quotes). Write as skills-capabilities/<name>/SKILL.md.proposed; never overwrite an existing skill name.
3. Bot: propose only when >=3 related skills form one craft that needs its own intelligence; name the closest existing bot and why it isn't enough (anti-redundancy gate).
4. Loop: propose only when a bot has a stable, repeatable workflow; give cadence and prompt.
5. Update continuity with one-line facts; never overwrite user-edited lines.
6. Every artifact goes to the sidebar as an approval card; nothing activates without Chris's yes.
7. Use native Hermes pieces first (hermes skills, hermes profile create, hermes cron, hermes serve approval.*) — verify with anser before building custom.

Pitfalls: capability mentioned once is not a skill; two bots must never own the same job.

## Evidence
> each of these topics are going to have their own loops where they turn context into skills, just like Hermes agent already does. And then when there's enough related skills where there needs to be an intelligence around that craft, then it groups those into a bot. When the bot is optimized where it has a workflow, then it should suggest a loop.
> everything here is the concept of taking context into skills, into bots, into loops
> I should be able to watch the wiki move around on its own, edit on its own, skills and bots and loops getting proposed all the time
