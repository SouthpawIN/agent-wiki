# SALT-core integration

SALT-core is the TurboFit low-VRAM dense-27B candidate: the upstream C99 SALT engine serving a 27B dense model on a 4 GB VRAM box via KV-cache offload to host RAM and weight/expert disk streaming, with a 262K-token n-gram context. It is registered as `candidate` and cannot be promoted to `released` until its qualification gate passes.

## Upstream engine

- **SALT - State Assured Latent-Trasition engine** — C99; paper: SALT: Reusable Computation for Stateful Language-Model Inference (https://zenodo.org/records/23111764)
- **Export:** Dry-run public export (2026-10-02) — not yet a release; public tree matches private `main` revision `ce0363260a488c96b951b4d826a188e1014575d4` (2026-10-02T10:58:17-04:00) for the exported runtime paths
- **Public repo:** https://github.com/SouthpawIN/SALT-core
- **Physical backends:** CPU, Metal, CUDA, HIP
- **Model weights:** not included in the export; artifacts have their own licenses
- **Server:** OpenAI-compatible /v1/models + /v1/chat/completions, single-flight FIFO, SSE streaming (server/serve.py, default port 8080)

Verified per the upstream README (the export's own claims):
- isolated Linux CPU and CUDA builds
- focused KV-compatibility tests
- public `make test` smoke suite (configuration, state control, Q4 byte identity, resource binding, server framing/session contracts)
- `make all` and `make -n test all` on Linux

Not qualified per the upstream README:
- real inference from the exported tree
- HIP/Metal build
- complete state/KV parity
