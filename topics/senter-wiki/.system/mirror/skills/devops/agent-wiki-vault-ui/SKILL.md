# Agent Wiki Vault UI

Single-file HTML dashboard over the agent-wiki vault (`~/Documents/Projects/Projects/vault-live.html`). All state is markdown in the vault; the HTML is a live view of it.

## Chris's locked style (do not re-litigate)
- **White on black** (`#060606`), monochrome — no blue tints; color only for muted terminal-palette bot/skill flags.
- **Sharp corners everywhere**, **thin white hairlines** (`rgba(255,255,255,.2)`).
- **Splash font = Collapse** (Bold titles/nameplates) + **Rules Compressed** (meta) — from Hermes `hermes_cli/web_dist/fonts/`, copied to vault `assets/fonts/`. Hard preference (the bot-creation splash font).
- **Dots, not triangles** — matches mind-map node language.
- **Hover underline grows full row width** (~0.4s in, ~0.08s out), title scales up slightly.
- **HERO block instead of helper text**: Collapse-bold topic title, thin underline, overview, meta line. Rotates on row hover AND every ~12s through recently-touched topics (watch-it-update-live).
- **Topic rows = title + integration dots ONLY.** No status pills, no sub-label text, no bot/skill name tags in rows. Connected integrations show as small brand SVG logos (GitHub, HuggingFace, YouTube, Discord, X — ~13px, dimmed till hover). Hover = solid matte black bg (`#000`), left rail bar grey→white, full-width underline, title scales.
- **Flags collapse to naked dots.** Bot/skill association flags render as bare colored dots (no border/box) when un-hovered; on row hover the dot expands into the full bordered label (Rules Compressed). Mind-map nodes and flag dots share the same visual grammar.
- **Row dots = FOUR METRIC ORBS (v11, supersedes skill dots, which superseded bot dots).** Chris dropped per-skill dots ("that's going to fill out fast"). Every topic row now carries exactly four `.orb`s after the title, fixed order + color: **context** gold `#e0af68` (~tokens = md chars/4), **skills** blue `#7aa2f7`, **agents** green `#9ece6a`, **loops** purple `#bb9af7`. **Final tuned values (v11.3, four nudge rounds — reuse, don't rediscover):** rest = **9px** solid dots, `.orbs` gap **12px** (Chris: smaller at rest "so the orbiting orbs do not run into each other"); row hover = **46px** with the VALUE inside at **1.75em, WHITE bold with a thin black outline** (`-webkit-text-stroke:.8px #000; paint-order:stroke fill` — black-on-color and then small white text were both rejected as hard to read; `1.9k` style for thousands), hover gap 14px. An ACTIVE orb (running loop, bot editing, skill in use) gets a tiny orbiting satellite dot (`.orb.on::after`, 4px, `@keyframes orbit`/`orbitBig`, radius 8px at rest / 28px hovered). **Orbit speed: 2.2s/lap at rest, 7s/lap on hover** — Chris wants the fast spin for a glance but "a lot slower" while reading a hovered row; never make hover faster than rest. API: `setOrbActive(topic, kind, on)`; `botActivity(bot)` lights that bot's home-topic **agents** orb for ~9s. Values are computed from the vault at build time (`topics/<name>/` md size + `skills/ agents/ loops/` dir counts) — a `stats(topic)` helper in the build script, not hand-typed. Integration logos FOLLOW the orbs at the same 13px (Chris: "keep the integration icons and use those as a size reference"). Skill NAMES now live only in the editor header (`#edSkills`); `.thead .sdots { display:none }`. Bots are shown via AVATARS, not dots.
- **Row hover scales EVERYTHING to the orb size (v12).** When the orbs bloom to 46px, the title grows too (`.thead:hover .tname { font-size:2.3em }`, transition on font-size not transform so the row reflows) and the integration SVGs grow 13→30px (`.thead:hover .idots .idot`), gap 14px; `.thead` min-height 44→60px. `body.idle` reverts all three. - **SKILLS and BOTS views are the WIKI element, not their own list style (v10.3, Chris: "use the same element… they're all markdown files").** Each view = a `.hero` block (hero ids generalized to classes `.hero/.heroTitle/.heroLine/.heroOverview/.heroMeta`; wiki keeps its ids too) + rows built by `mkTopic({name,path,overview,meta,leading,tags,body})` that emit the canonical `.topic > .thead + .tbody > .tbody-inner` markup, then `initTopic(t)` (toolbar with `data-path` label, drag, click→`openEditor`). ## Pitfalls
- **Live-page findings behind the three 2026-09-02 tail regressions — check these FIRST when the strip or cards misbehave.** (1) *Hero "shines through" the open top strip*: `#topstrip.on` and `#topnav` computed `background-color: rgba(0,0,0,0)` — the nav was only ever drawn ON the hero, never over it. An overlay that must cover content needs an explicit opaque page-black bg and should hide `#hero` (`visibility`/`opacity`, ~120ms) while open. (2) *Nav "never opens" / "opens slowly"*: the CLOSED strip's hit zone had shrunk to **16px** (opens at pointer y=4, closes at y=40) after repeated "don't push/cover the hero" fixes — probe the closed height at the user's viewport with pointer moves at 3+ y values; brief a floor (≥48px invisible zone) as a design constraint. Headless open latency was 61ms + 140ms transition, so "slow" from the user usually means the trigger is missable, not the animation. (3) *Gold returns on already-approved cards after un-hover*: a static `.done` card computes white correctly — the bug is the RE-RENDER path: the bridge replays the last 60 SSE events on reconnect, so an `approval/pending` replayed after its `decided` recreates a gold card, and collapse/expand rebuilds from the pending Map. Fix at the source: a client `decided` Set the card builder refuses, server replay filtered against `pending/`, all re-renders from one state object. Related: the gold-dissipation wipe animated a registered `@property --wipe` — suspect custom-property interpolation in the Electron webview before anything else when a CSS effect "never plays"; rebuild on `clip-path`/`mask-position`. Diagnose by dumping handler source + `document.styleSheets` cssText headless BEFORE re-briefing.
- **Never build the full-page editor as a `position:fixed` overlay on a list row.** Two failures Chris saw (v6.2–6.7): (a) content top-anchored with ~⅔ of the pane dead black below NOW — the overlay had no flowing height; (b) the row lives inside the scrolling `#view-wiki` container, which clipped it ("cuts off early"). Moving the node to `document.body` was still wrong. Correct fix = a real sibling view (`#view-editor`) with the wiki skeleton (see the EDITOR VIEW bullet).
- **The collapsed row's `.tbody { max-height:0; overflow:hidden }` follows the node when you move it.** After moving a `.tbody` into `#edBody`, the body renders EMPTY (only the toolbar shows) unless you add `#edBody .tbody { max-height:none !important; overflow:visible !important; }`. Caught only by screenshot — see Verify visually.
- **Never chain many `patch()` calls on this file** — one failed/overlapping patch ate the whole `<body>` (JS landed in `<style>`). Rebuild with `write_file` for big changes; verify token counts after patches.
- **After any patch run, verify the file didn't shrink** — a bad slice replaced half the doc (34k → 10.5k chars) silently. `read_file` or check for sentinel tokens (topnav, view-feed, FLEET STREAM) before opening the preview.
- **`.tbody` must be a SIBLING after `.thead`, never inside it.** A regex injection once placed the expanded body inside the flex title row → title rendered to the LEFT of the content ("expands weird"). When row markup drifts, rebuild ALL rows from one canonical template via regex (`row_rebuild`: extract tname/idots/richest tbody, re-emit `<div class="topic">thead\n tbody</div>`) rather than spot-patching — see `references/row-template.md`.
- Regex-based content injection needs a structure assertion after: count `class="topic`, `tbody-inner`, `class="tag"` and grep for `thead">.*<div class="tbody"` (must be 0). Also count every `id="…"` you touched — a `re.sub` over the BOTS view once left a duplicate `<div id="bots-list">` + stray `</div>` (and a stray `◈</span>`), which broke the view silently.
- **Playwright probes and auto-hiding chrome: drive hidden controls with `page.evaluate(() => el.click())`, not `page.click(selector)`.** Two probes timed out with `subtree intercepts pointer events` because the floating nav had hidden itself (correct behavior!) or a sticky hero overlapped the target. `page.click` waits for a visible, unobstructed element; when the element is supposed to be hidden most of the time, a DOM-level `.click()` proves the handler while a separate `boundingBox()` check (after `mouse.move(600,5)` to summon the nav) proves the layout. Don't read a probe timeout as a page bug — first ask whether the element is *meant* to be hidden right now.
- **Removing a UI element = remove ALL its JS references too.** After deleting the stream input, a leftover `document.querySelector('#input textarea').addEventListener(...)` at top level would throw on null and kill the ENTIRE script (every later handler dead). Grep for the id/class across CSS + JS (`#input`, `ta.`), then `node --check`; a null-deref isn't a syntax error, so also skim the top-level statements that reference the removed node.
- CSS-only tricks for expand/collapse flags: `font-size:0` on collapsed state breaks nothing but must be restored on hover — keep the dot `::before` and the label font-size as separate hover toggles.
- **Per-variant colors via a custom property: reference `var(--c)` directly, not `currentColor`.** The orbs first rendered as a uniform pile because `background:currentColor` + `color:var(--c)` (set by `.orb[data-k=…]` variants) didn't resolve as expected across the pseudo-element/satellite chain. Writing `background:var(--c)` / `box-shadow:0 0 6px var(--c)` on the orb AND its `::after` fixed it instantly. Same rule for any element whose color is a data-attribute variant.
- **Multi-part requests arriving mid-tool-call (OUT-OF-BAND) restate the design — treat the latest as the spec.** Chris's orb idea landed while a hatch was running; the right move was to fold it into the same build pass and update the locked-style bullet (decision flip), not to finish the old plan first.

- **`const` data tables must be declared ABOVE any init-time code that reads them (TDZ).** Factoring `wireIcons` out of the click-time `openEditor` into `initTopic` (runs at load) made `LINKS`/`REPO` — declared far down the script — throw `Cannot access 'LINKS' before initialization`, which killed the whole script: no editor, no cards, no avatar, and the preview showed NOTHING wrong (the on-page error toast only catches runtime `error` events after load). Hoist every `const LINKS/REPO/TOPIC_BOT/BOTCOLOR…` to the top of `<script>` (slice + reinsert in the build script) whenever you move a function from lazy to eager. `node --check` does NOT catch this — only the headless probe does (see Verify).
- **Playwright `boundingBox()` returns null for hidden elements** — the tour script crashed on `#edBack` when the editor wasn't open. Guard every `bb.x` with `if (b)` and fall back (e.g. `Escape`).
- **Parallel shell jobs: write a script file, never inline `( … ) & ( … ) & wait` chains.** zsh threw `parse error near '('` on the inline form (em-dashes in quoted args + subshells). `scripts/hatch-fleet.sh` (bash function + `&` + `wait`, per-job logs) is the shape. Also: `nohup/disown/setsid` are refused by the terminal tool — use `terminal(background=true, notify=true)`. Background jobs DIE when Chris interrupts a turn (exit -15, `termination_source: process.kill`) — after any interrupt, `process poll` the job and relaunch; tell him it was the interrupt, not a failure.
- **Syntax-check the extracted `<script>` with node before reloading**: slice `<script>…</script>`, write to /tmp, `node --check`. Cheap and caught nothing this session — but a runtime smoke run with a stubbed `document` (see the review transcript pattern) confirmed the script reaches its end; use it when a view renders empty.
- **`drive_preview click` on nav tabs is unreliable** — synthetic clicks sometimes don't reach the handler and the screenshot still shows WIKI, which looks exactly like a switcher bug. Before debugging the page, load `vault-live.html?view=<tab>` and screenshot; if that works the page is fine. If the preview also ignores the query (it re-serves the cached default view), write a throwaway sibling `_test-<view>.html` = the same file plus `setTimeout(()=>showView('<view>'),300)`, open THAT, screenshot, then delete it. `drive_preview hover` doesn't hold through a `computer_use capture` either — hover states must be judged by Chris or captured via the Playwright tour (below). A temporary on-page debug badge (`on=<view ids> | disp=… | rows=N`, updated every 500ms) is a fast way to see real DOM state in the screenshot — remove it after.
