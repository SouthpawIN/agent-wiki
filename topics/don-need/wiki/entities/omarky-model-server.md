# Omarky / Omarqi — the main model server

On 2026-09-16 Chris referred to a model server he calls **"Omarky"** (he also spells it **"Omarqi"**) as the place where he has models downloaded and where he expects the **main model server** to live: *"I want you to include all of the models that I have downloaded on Omarky as well"* and *"Omarqi, which is going to be the main model server anyways."*^[raw/inbox/2026-09-16.md]

Two facts land here:

- **Spelling is unstable** — the record shows both "Omarky" and "Omarqi." Treat as one system; confirm the canonical name with Chris before writing it into anything durable.
- **It is the future centerpiece** — Chris frames Omarqi as *"going to be the main model server anyways,"* i.e. the convergence point for all his models, not just one box among many. This is why he insists it be included when cataloguing models.

The request is scoped broadly: *"all my models downloaded … across all my systems"* — so the inventory must span the current machine, the HP, and Omarqi, with Omarqi as the anchor.^[raw/inbox/2026-09-16.md]

This builds directly on the model-visibility thread in [[topics/don-need/wiki/concepts/session-model-autonomy|Session model autonomy]] (he wants the real model name surfaced, not hidden as `auto`) and the [[topics/don-need/wiki/concepts/turbofit-model-fallback|TurboFit missing-model fallback]] preference (the runtime should know its own models and fall back rather than fail). It also extends the [[topics/don-need/wiki/concepts/freeing-disk-space-after-migration-to-hp|freeing disk space after migrating games to the HP]] cleanup — the systems are already being consolidated (games moved to the HP), and models are the next thing on the list.
