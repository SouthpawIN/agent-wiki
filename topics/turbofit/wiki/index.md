## Concepts
- [[topics/turbofit/wiki/concepts/131k-deferred-candidates|131K Deferred Candidates]] — A number of newly downloaded candidate artifacts were not benchmarked at 131K because model-plus-KV size exceeds the stable 32 GB Mac fit before testing begins.
|- [[topics/turbofit/wiki/concepts/compression-timeouts|Compression Timeouts]] — Hermes failed with timeout or fallback behavior during compression operations because local TurboFit memory pressure interrupted long-running work.
|- [[topics/turbofit/wiki/concepts/bonsai-colibri-deprioritization|Bonsai and Colibri Deprioritization]] — Chris explicitly redirected all focus from Bonsai/Colibri candidates to getting Ornith MLX configured into TurboFit on 2026-09-07; both models failed to load (custom Maple format / missing config.json).
- [[topics/turbofit/wiki/concepts/dflash2-compat-boundary|DFlash2 Compatibility Boundary]] — DFlash2 draft models are not interchangeable across runtimes. On this box the boundary is concrete: MTPLX cannot use DFlash2, and Unleashed+DFlash2 only works through the dedicated `dflash2-llama.cpp` fork with a narrow valid flag set ^[raw/inbox/2026-09-07.md, raw/inbox/2026-09-07-from-senter-wiki.md].
- [[topics/turbofit/wiki/concepts/dflash2-mplx-incompatibility|DFlash2 MTPLX Incompatibility]] — DFlash2 draft models are incompatible with MTPLX's native MLX MTP heads. MTPLX uses native MLX MTP architecture, while DFlash2 is a CUDA/llama.cpp diffusion draft model.
- [[topics/turbofit/wiki/concepts/hermes-model-switching-noise|Hermes Model Switching Noise]] — The active Hermes model switched multiple times during TurboFit work without Chris initiating the changes, including to `meituan/longcat-2.0:free` and `stepfun/step-3.7-flash:free` ^[raw/inbox/2026-09-07.md].
- [[topics/turbofit/wiki/concepts/model-switching-pain|Model Switching Pain]] — During this session the active model changed multiple times outside Chris’s intent, including to `anthropic/claude-fable-5.1`, `openai/gpt-6-astra`, `meituan/longcat-2.0:free`, `muse-spark-1.3-contributor-free`, and `stepfun/step-3.7-flash:free` ^[raw/inbox/2026-09-06.md].
- [[topics/turbofit/wiki/concepts/mtplx-32gb-memory-and-evidence-reliability|MTPLX 32GB Memory and Evidence Reliability]] — Captures two distinct reliability concerns for MTPLX on this box: 131K memory overcommit, and postcommit artifacts that can't be treated as finished TurboFit evidence without a Hermes window capture.
- [[topics/turbofit/wiki/concepts/mtplx-context-overcommit|MPLX Context Overcommit]] — On the 32 GB Mac, `mtplx serve` with `--context-window 131072` loads the model in 6–9 s and installs the native MTP draft head, but the printed memory plan marks the fit OVERCOMMITTED and warns that the KV cache will force cache shedding or swap.
- [[topics/turbofit/wiki/concepts/mtplx-foreground-preemption|MPLX Foreground Preemption]] — When MTPLX handles long-running Hermes foreground work, postcommit records show `cross_session_foreground_preempted` and `foreground_preempted_postcommit`, and `retokenized_history_mismatch` makes those artifacts unreliable as final TurboFit evidence.
- [[topics/turbofit/wiki/concepts/turbofit-session-mismatch|TurboFit Session Mismatch]] — MTLPX generation events show foreground/preemption behavior and session-store mismatch that make some TurboFit captures unreliable as finished-state evidence ^[raw/inbox/2026-09-07.md].

## Decisions
- [[topics/turbofit/wiki/decisions/aux-model-selection|Aux Model Selection]] — Auxiliary and compression routing is Maple MLX on `127.0.0.1:11612`, 131k context, served with `deepgrove-ai/mlx-lm-deepgrove` ^[raw/inbox/2026-09-06.md].
- [[topics/turbofit/wiki/decisions/candidate-quant-preference|Candidate Quant Preference]] — **Decision/Preference:** When comparing GGUF vs MLX for new local candidates, prefer the Q3 quant when model pages describe it as near base-model quality.
- [[topics/turbofit/wiki/decisions/context-sizing|Context Sizing]] — Local TurboFit contexts are set to 131,072 tokens for both main and aux ^[raw/inbox/2026-09-06.md].
- [[topics/turbofit/wiki/decisions/context-window-decision|Context Window Decision]] — **Decision:** Lock in 65K context as the stable daily driver on this 32 GB M1 Mac, with 131K reserved for rare long-context needs where speed is not critical.
- [[topics/turbofit/wiki/decisions/fallback-model-order|Fallback Model Order]] — The active model preference order should preserve explicit user choice and avoid silently switching to `stepfun/step-3.7-flash:free` ^[raw/inbox/2026-09-06.md].
- [[topics/turbofit/wiki/decisions/local-main-provider|TurboFit Local Main Provider Decision]] — What Chris wanted: the smartest feasible local runtime as Hermes main, with verified evidence, not just Hermes internal logs. Chris later redirected all priority to getting Ornith routed into TurboFit as the main provider.
- [[topics/turbofit/wiki/decisions/main-model-selection|Main Model Selection]] — Initial decision: Main inference and vision is Unleashed 27B + DFlash2 draft on `127.0.0.1:11606`, Metal, 131k context ^[raw/inbox/2026-09-06.md].
- [[topics/turbofit/wiki/decisions/mtplx-main-provider|MTPLX Main Provider]] — Make `Youssofal/Qwen3.8-27B-MTPLX-Optimized-Speed` via `mtplx serve` the main TurboFit provider and remove Maple/Unleashed as co-resident models to reclaim disk space. This was superseded by Ornith routing.
- [[topics/turbofit/wiki/decisions/unleashed-backup|Unleashed Backup]] — Keep Unleashed Q3_K_XL as the safe long-context backup when MTPLX overcommits memory or Hermes reloads fail.
