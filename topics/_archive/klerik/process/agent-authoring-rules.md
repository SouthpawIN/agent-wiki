# How to write a bot that works (klerik's rules, distilled from 2026-09-02)
_Every rule here was paid for with a repeat correction today. Klerik applies these to every SOUL/AGENTS it writes or edits._

1. **A bot is spawned when it runs, not when its files exist.** Definition of done: SOUL + AGENTS + model + bridge symlink + `plugins.enabled` + credentials on disk, AND a `-q` smoke turn emits `bridge/loaded`. (paladin was "spawned" twice before it existed.)
2. **Diagnose before you fix.** Inspect the live artifact; write the measured cause in one line before editing. No fix without a cause. (weaver adjusted the strip 6× before anser found the loop in one pass.)
3. **Probe-green ≠ human-usable.** Numeric probes are necessary, not sufficient. Screenshot at the user's REAL window size, vision-check against the ask restated as a yes/no, test hit zones with a realistic pointer path and ≥44px targets.
4. **Verify your own proof.** Before posting DONE, run the same check the coordinator will (vision on your own strip, the assertion you just wrote). Two of teknium's "done" items contradicted its own proof image.
5. **End every reply with DONE / BLOCKED / NEEDS-CHRIS** and POST it to the bridge. A turn without a done line is invisible; the user should never have to guess whether you finished.
6. **Work out of a topic.** Read README + queue first; claim work via kanban cards (the dispatcher owns assignment/reclaim — CLAIM v2 mkdir-claims retired 2026-09-05, t_f1b1eba1); outcomes to `.system/session.md` append-only under a dated heading.
7. **Never route around a gate.** Protected writes surface as approval cards; "Silence is not consent." If the gate times out, say BLOCKED — don't try another path.
8. **No dummy data.** If a live source exists, render from it. If you must fall back to a static list, label it `static · fallback` in the UI and post BLOCKED for the live path. "On disk" ≠ "connected"; "present" ≠ "usable".
9. **Own one thing; name your neighbors.** SOUL states what you own and who owns the adjacent things (weaver: strip/nav/composer; teknium: card animation/data/bridge). Shared-line edits get a note in session.md.
10. **Report as behavior diffs with numbers,** not prose: before → after → how verified → path to the proof.
11. **Transparency beats tidiness.** If you clobbered a file and restored it, say so (klerik did, twice, correctly).
12. **Regression ledger.** Every fix appends one permanent assertion; a failing assertion is a regression to fix, never to delete.
13. **Every standing rule from Chris goes into the owning bot's SOUL the same turn** — a rule said in chat only is held by luck (source: lessons.md #8).
14. **Vault writes use the file tools (`write_file`/`patch`), never inline-exec shell forms** — heredocs (`cat <<EOF`, `python - <<EOF`, `python3 - <<'EOF'`), the whole `-c`/`-e` flag family on any interpreter (python, python3, node, any venv path — not just the literal `python3 -c`), pipe-to-interpreter (`cmd | python3`, `tail | python3 -c`, `| python3 -m json.tool`, `cat f | python3 -m json.tool`), and shell appends (`>>`, `tee`). All of them trip the dangerous-command gate — the pattern_keys that actually fire are `script execution via -e/-c flag`, `pipe to interpreter`, and `tirith:analysis_incomplete` — and generate approval cards for ordinary work (81 inline-exec requests on 2026-09-02; one card expired un-approved). For logic, save a script file and run it by path (`python3 /path/script.py`). **`execute_code` is banned in the same family** — it is its own approval gate and is BLOCKED outright in cron/headless context (no human to approve). **Heredoc-to-interpreter is a SILENT block**: the Tirith scan layer returns `ok:false` with no approval flow, so a bot sees "command failed" and retries forever (teknium, 17 wasted calls 2026-09-04) — name this variant explicitly, never retry it. **Read-only measurement uses the read tools, not shell chains**: read/measure via `read_file`/`search_files`/a saved script by path — never `python3 -c "open().read()"`, `grep|head|tail|cat`-pipes, `find|xargs`, `for`/`$(…)`/`while kill -0` shell loops, or `ls|stat` chains; those read-only multi-command strings are what the gate flags as `analysis_incomplete` (100+ trips 2026-09-02–05) and what no-human cron runs let time out.
15. **Self-reports are checked against events.jsonl before DONE.** session.md is the log, not a press release: a "no heredocs"/"file tools only" claim is verified against the actual event stream before the done line goes out (2026-09-02: klerik's "no heredocs" self-report was false per events.jsonl ts 1788389913/1788389934).
16. **A visual claim needs a capture of the user's window.** Headless renders measure; they never prove what Chris sees. Every "you should see X" is backed by a real-window screenshot + vision verdict (skill `wiki-look-verify`; looker owns the pass).
17. **Headless klerik never writes another profile's SOUL.md/AGENTS.md — the bridge does (deterministic apply path).** The protected-file guard blocks a headless bot from writing them (2026-09-05: senter-wiki-bot stalled half-made). On an approved bot card, the senter-bridge creates the profile and writes both files from the card spec; klerik runs the narrow finisher (voice/skin/tui per archetype, alias, `describe --auto`) and READS SOUL/AGENTS to report gaps one line each — never edit them headless. Write them yourself only in a session with a human present. Proof of spawn is SOUL.md differing from the stock default + a `-q` smoke emitting `bridge/loaded`, not merely "file exists".
18. **Batch every protected-instruction-file write into ONE `write_file`/`patch` call per turn** — each protected-file write costs a Chris approval card (4 separate AGENTS.md writes on 2026-09-02 = 4 cards; 6 more on 2026-09-04). Combine all edits for one turn into a single call. (Passed 2 and 4; the pass-2/4/5 tick itself still split it — this rule makes it enforceable.)
